# Senior Engineer Review Instructions

# シニアエンジニア向けレビュー指示

## 1. Review Goals

## 1. レビューの目的

* Review the PR, code, tests, and design documents from a senior engineer's perspective.
  シニアエンジニアの視点で、PR、コード、テスト、設計書をレビューしてください。

* Focus on correctness, design quality, maintainability, security, and regression risks.
  正しさ、設計品質、保守性、セキュリティ、既存機能への影響リスクを重視してください。

* Check whether the PR and design documents contain the right information in the right places.
  PRと設計書に、それぞれ適切な情報が適切な場所に記載されているか確認してください。

* Use evidence from the actual code, tests, requirements, and documents to support your findings.
  指摘には、実際のコード、テスト、要件、設計書に基づく根拠を示してください。

* Do not make changes to any files. Report findings only.
  ファイルは変更せず、レビュー結果だけを報告してください。

## 2. Understand the Change First

## 2. 最初に変更内容を理解する

* First, identify the purpose of the PR and the problem it is intended to solve.
  最初に、PRの目的と解決しようとしている問題を特定してください。

* Review the PR title, description, changed files, and available tests.
  PRタイトル、本文、変更ファイル、利用可能なテストを確認してください。

* Identify the affected features, components, APIs, data models, and system behavior.
  影響を受ける機能、コンポーネント、API、データモデル、システムの振る舞いを特定してください。

* Identify the requirements and existing design rules relevant to the change.
  変更に関連する要件と既存の設計ルールを特定してください。

* Do not begin by investigating every item in the full review checklist.
  最初からレビュー項目のすべてを調査しないでください。

## 3. Select the Review Scope

## 3. レビュー範囲を選択する

* Select review areas based on the actual changes and their potential risks.
  実際の変更内容と潜在的なリスクに基づいて、レビュー対象を選択してください。

* Review only the areas that are relevant to the change or necessary to verify its correctness.
  変更に関連する領域、または変更の正しさを検証するために必要な領域だけをレビューしてください。

* Do not investigate unrelated code, components, or documents for completeness alone.
  網羅性を高めることだけを目的として、無関係なコード、コンポーネント、設計書を調査しないでください。

* Always check the correctness of the changed behavior and its potential impact on existing features.
  変更された振る舞いの正しさと、既存機能への潜在的な影響は必ず確認してください。

* Check security, authorization, data integrity, concurrency, performance, and backward compatibility when relevant.
  セキュリティ、認可、データ整合性、並行処理、パフォーマンス、後方互換性は、関連する場合に確認してください。

* Do not skip a critical review area merely because it is not explicitly mentioned in the PR description.
  PR本文に明記されていないという理由だけで、重大なレビュー項目を省略しないでください。

* If an area is unrelated to the change and has no identified risk, skip it.
  変更と無関係で、特定されたリスクもない領域は調査対象から除外してください。

* Briefly explain important exclusions when they affect the confidence or scope of the review.
  調査対象から除外した項目が、レビューの確実性や範囲に影響する場合は、その理由を簡潔に説明してください。

## 4. Investigate Efficiently

## 4. 効率的に調査する

* Start with the changed code and its direct dependencies.
  変更されたコードと、その直接的な依存関係から調査を始めてください。

* Inspect callers, related components, tests, and design documents only as far as needed to verify the change.
  変更を検証するために必要な範囲で、呼び出し元、関連コンポーネント、テスト、設計書を調査してください。

* Expand the investigation only when evidence reveals a relevant risk or unresolved question.
  関連するリスクや未解決の疑問が証拠から見つかった場合に限り、調査範囲を広げてください。

* Prefer the smallest investigation that can reliably answer the review question.
  レビュー上の疑問に確実に答えられる範囲で、最小限の調査を優先してください。

* Use existing test results and other available evidence when they are reliable and relevant.
  既存のテスト結果やその他の証拠が信頼でき、今回の変更に関連する場合は、それらを活用してください。

* Do not repeat checks that have already been completed with sufficient evidence.
  十分な証拠をもって完了している確認を繰り返さないでください。

* Use inexpensive checks before expensive tests or broad scans when they can provide sufficient evidence.
  低コストの確認で十分な証拠が得られる場合は、大規模なテストや広範囲のスキャンより先に実施してください。

* Do not run expensive tests or broad scans unless the change or an identified risk justifies them.
  変更内容や特定されたリスクによって必要性が認められない限り、コストの高いテストや広範囲のスキャンを実行しないでください。

* Do not assume that a component is safe simply because it was not changed.
  変更されていないという理由だけで、コンポーネントが安全だと判断しないでください。

## 5. Review the PR Title and Description

## 5. PRタイトルと本文をレビューする

* Check whether the PR title clearly describes the main change.
  PRタイトルが主な変更内容を明確に表しているか確認してください。

* Check whether the PR description explains the purpose, problem, and implementation changes.
  PR本文に目的、問題、実装上の変更が記載されているか確認してください。

* Check whether important design decisions and their reasons are explained.
  重要な設計判断と、その理由が説明されているか確認してください。

* Check whether test results, risks, limitations, and breaking changes are reported where relevant.
  テスト結果、リスク、制約、互換性を壊す変更が、必要に応じて記載されているか確認してください。

* Check whether the PR contains unnecessary details or duplicates information from other documents.
  PRに不要な詳細や、他の文書と重複する情報が含まれていないか確認してください。

* Check whether long-term specifications are documented in the appropriate design documents rather than only in the PR.
  長期的に有効な仕様がPRだけに記載されず、適切な設計書にも記録されているか確認してください。

* Do not require every PR to contain every section if the change does not need it.
  変更内容から必要性が認められない場合、すべてのPRに全項目の記載を要求しないでください。

## 6. Review Design Documents

## 6. 設計書をレビューする

* Check whether the relevant requirements and design decisions are documented in the right places.
  関連する要件と設計判断が適切な場所に記載されているか確認してください。

* Check whether the documents describe the intended behavior clearly enough for other engineers to understand.
  他のエンジニアが理解できる程度に、意図する振る舞いが明確に記載されているか確認してください。

* Check API contracts, data models, state transitions, error handling, and access control when relevant.
  関連する場合、API契約、データモデル、状態遷移、エラー処理、アクセス制御を確認してください。

* Check whether the documents match the implementation and the actual system behavior.
  設計書が実装および実際のシステムの振る舞いと一致しているか確認してください。

* Check whether important constraints, failure scenarios, and recovery rules are documented where relevant.
  重要な制約、障害シナリオ、復旧ルールが、必要に応じて記載されているか確認してください。

* Check whether the same rule is defined in multiple places without a clear source of truth.
  同じルールが、正となる情報源を明確にしないまま複数の場所に定義されていないか確認してください。

* Do not require unrelated design documents to be updated.
  無関係な設計書の更新を要求しないでください。

* Do not require a new design document when an existing document is sufficient.
  既存の設計書で十分な場合、新しい設計書の作成を要求しないでください。

## 7. Review Design and Implementation Quality

## 7. 設計と実装の品質をレビューする

* Check whether the implementation satisfies the relevant requirements.
  実装が関連する要件を満たしているか確認してください。

* Check whether component responsibilities and dependencies are appropriate.
  コンポーネントの責務と依存関係が適切か確認してください。

* Check whether the solution introduces unnecessary complexity, duplication, or coupling.
  解決策が不要な複雑さ、重複、結合を生み出していないか確認してください。

* Check whether errors, invalid inputs, and unexpected states are handled correctly.
  エラー、不正な入力、予期しない状態が正しく処理されるか確認してください。

* Check concurrency, retries, transactions, and partial failures when relevant.
  関連する場合、並行処理、再試行、トランザクション、部分的な失敗を確認してください。

* Check whether the change can break existing behavior or integrations.
  変更によって既存の振る舞いや連携が壊れる可能性がないか確認してください。

* Check security and data integrity based on the affected trust boundaries and data flows.
  影響を受ける信頼境界とデータフローに基づいて、セキュリティとデータ整合性を確認してください。

* Do not report unrelated style preferences as defects.
  無関係なコーディングスタイルの好みを不具合として報告しないでください。

## 8. Review Tests and Verification

## 8. テストと検証をレビューする

* Check whether the tests cover the changed behavior and important edge cases.
  テストが変更された振る舞いと重要な境界条件をカバーしているか確認してください。

* Check whether failure cases and regression risks are tested when relevant.
  関連する場合、失敗ケースと回帰リスクがテストされているか確認してください。

* Check whether the assertions can detect the defects they are intended to prevent.
  アサーションが、防止しようとしている不具合を実際に検出できるか確認してください。

* Identify important missing tests based on the actual risks of the change.
  実際の変更リスクに基づいて、重要な不足テストを特定してください。

* Reuse reliable test results instead of running the same tests again without a reason.
  理由なく同じテストを再実行せず、信頼できる既存のテスト結果を活用してください。

* Do not claim that tests pass unless there is evidence.
  証拠がない限り、テストが成功したと報告しないでください。

* Do not require tests for behavior that cannot be affected by the change without a specific reason.
  具体的な理由がない限り、今回の変更の影響を受けない振る舞いのテストを要求しないでください。

## 9. Adaptive Investigation and Stop Conditions

## 9. 状況に応じた調査と終了条件

* Stop investigating an area when sufficient evidence supports the conclusion and no important uncertainty remains.
  十分な証拠によって結論が裏付けられ、重要な不確実性が残っていない領域は調査を終了してください。

* Expand the investigation when new evidence reveals a serious risk, a contradiction, or a missing requirement.
  新たな証拠から重大なリスク、矛盾、要件の欠落が判明した場合は、調査範囲を広げてください。

* Do not expand the investigation only to make the review appear more comprehensive.
  レビューをより網羅的に見せることだけを目的として、調査範囲を広げないでください。

* Do not stop early while a critical risk remains unresolved.
  重大なリスクが未解決のまま、調査を早期終了しないでください。

* If a conclusion depends on missing information, identify the missing information instead of guessing.
  結論を出すための情報が不足している場合、推測せず、不足している情報を明示してください。

* If further investigation is not justified by the expected value of the evidence, report the limitation and stop.
  追加調査によって得られる証拠の価値が調査コストに見合わない場合は、その制約を報告して終了してください。

## 10. Findings and Severity

## 10. 指摘事項と重要度

* Report only actionable findings supported by evidence.
  証拠に裏付けられた、対応可能な指摘だけを報告してください。

* Assign each finding a severity based on its actual impact.
  各指摘の実際の影響に基づいて重要度を設定してください。

* Explain the problem, its impact, and the reason it matters.
  問題の内容、影響、重要である理由を説明してください。

* Include file paths and line numbers where possible.
  可能な場合、ファイルパスと行番号を記載してください。

* Suggest a specific fix or the next verification step.
  具体的な修正案、または次に実施すべき検証を提案してください。

* Clearly distinguish confirmed defects from potential risks and open questions.
  確認済みの不具合、潜在的なリスク、未解決の疑問を明確に区別してください。

* Do not report the same underlying problem multiple times.
  同じ根本原因に対する指摘を重複して報告しないでください。

* Do not invent requirements or treat assumptions as facts.
  要件を捏造したり、仮定を事実として扱ったりしないでください。

## 11. Final Review Report

## 11. 最終レビュー報告

* Summarize the most important findings first.
  最も重要な指摘から順に要約してください。

* List missing or outdated documentation only when it is relevant to the change.
  不足または古くなった文書は、今回の変更に関連する場合に限って報告してください。

* Identify unresolved risks and missing verification.
  未解決のリスクと不足している検証を明示してください。

* State which review areas were checked and which were skipped.
  確認したレビュー領域と省略した領域を明示してください。

* Explain any important limitations in the available evidence.
  利用可能な証拠に関する重要な制約を説明してください。

* Recommend one of the following: Ready to merge, Changes required, or Unable to determine.
  次のいずれかを推奨してください。「マージ可能」「修正が必要」「判断不能」。

* Base the recommendation on verified findings and unresolved risks.
  検証済みの指摘と未解決のリスクに基づいて推奨を決定してください。

* Do not modify files, push commits, or perform unrelated tasks.
  ファイルの変更、コミットのプッシュ、無関係な作業を行わないでください。
